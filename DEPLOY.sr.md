# Постављање ВАСИОНА платформе на Vercel

*(For English, see [DEPLOY.md](./DEPLOY.md))*

## 1. Поставити пројекат у Git репозиторијум
```bash
cd vasiona-platform
git init
git add .
git commit -m "Иницијална ВАСИОНА платформа"
# направити репозиторијум на GitHub/GitLab, затим:
git remote add origin <адреса-вашег-репозиторијума>
git push -u origin main
```

## 2. Увоз у Vercel
- Отићи на vercel.com → **Add New… → Project** → увести репозиторијум.
- Framework preset: Next.js (препознаје се аутоматски).

## 3. Додати Postgres складиште
- У Vercel пројекту → картица **Storage** → **Create Database** → Postgres
  (Vercel Postgres, или повезати Neon/Supabase — обе опције раде са
  `@vercel/postgres` све док су стандардне `POSTGRES_URL*` променљиве
  подешене).
- Ово аутоматски убацује `POSTGRES_URL`, `POSTGRES_URL_NON_POOLING` итд. у
  environment променљиве пројекта — није потребно ручно их подешавати.

## 4. Подесити environment променљиве
Project Settings → Environment Variables → додати (видети `.env.example`):
- `CRON_SECRET` — било који дуг насумичан низ карактера. **Важно:** Vercel
  аутоматски прилаже ово као Bearer токен приликом позивања cron задатка,
  што `app/api/cron/fetch-tles/route.ts` проверава.
- `HYPOTHETICAL_FEE_USD_PER_PASS` (подразумевано 25)
- `INCLINATION_COVERAGE_FACTOR` (подразумевано 0.75)
- `ORBITS_PER_DAY_ASSUMED` (подразумевано 15)
- `CELESTRAK_GROUP` (подразумевано `active`) — видети напомену испод о
  ограничењима плана.

## 5. Распоред cron задатка
`vercel.json` је већ подешен да се извршава дневно у 03:00 UTC:
```json
{ "crons": [{ "path": "/api/cron/fetch-tles", "schedule": "0 3 * * *" }] }
```
- **Hobby план:** Vercel ограничава учесталост cron задатака на бесплатном
  нивоу — проверити ограничења тренутног плана пре подешавања учесталости
  веће од дневне; у супротном ће поставка бити одбијена или тихо ограничена.
- **Pro план или виши:** учесталост се може безбедно повећати, нпр. на свака
  2 сата: `"0 */2 * * *"`. Сателити се крећу брзо (~90-минутне орбите), тако
  да чешће очитавање хвата више стварних прелета — дневно очитавање ће
  видљиво потценити број прелета.

## 6. Трајање функције / величина каталога
CelesTrak група `active` је пун каталог од ~16.500 сателита. Прорачун свих
њих у једном serverless позиву може приближити временско ограничење Vercel
функције на нижим плановима. Опције уколико cron задатак истекне:
- Подесити `CELESTRAK_GROUP` на мању групу (нпр. `stations`, `starlink`,
  `oneweb` — видети https://celestrak.org/NORAD/elements/ за пун списак
  назива група) ради тестирања са мање објеката.
- На Pro/Enterprise плану, повећати `maxDuration` у
  `app/api/cron/fetch-tles/route.ts` (тренутно подешено на 60 секунди; Pro
  дозвољава више).

## 7. Прво постављање и ручно тестирање
Након постављања:
```bash
curl -H "Authorization: Bearer ВАШ_CRON_SECRET" https://<ваша-апликација>.vercel.app/api/cron/fetch-tles
```
Ово покреће исту логику коју ће Vercel Cron извршавати по распореду —
употребити за проверу целог тока (CelesTrak преузимање → пропагација →
геозаштита → унос у Postgres) пре чекања на распоред.

Затим отворити `https://<ваша-апликација>.vercel.app/?lang=sr` за контролну
таблу на српском (или без параметра `?lang=` за енглески).

## 8. Замена оквира граница Србије стварним полигоном (препоручено пре ослањања на ово)
`lib/serbia.ts` тренутно користи поједностављен правоугаони оквир. За
прецизност у продукцији, заменити стварним полигоном (нпр. из Natural Earth
или GADM извора) и провером тачка-у-полигону — датотека `db/schema.sql`
садржи закоментарисану PostGIS табелу (`country_borders`) као полазну тачку
уколико желите да чувате полигон у Postgres бази уместо тврдог кодирања у
`lib/serbia.ts`.
